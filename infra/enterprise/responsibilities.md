# Enterprise operations and offline support responsibilities

This is a candidate operating model to agree before sale, not an executed support contract or SLA.

| Area                  | Vendor responsibility                                                                                                                                                                          | Customer/operator responsibility                                                                                                                                                    |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Release integrity     | Sign reviewed versioned artifacts, publish trusted public-key fingerprints through an authenticated channel, ship SBOMs/notices, list exact qualified versions/architectures and upgrade paths | Verify signatures/checksums before execution; retain previous approved artifacts; control host access and change windows                                                            |
| License               | Deliver installation/customer-bound offline license, renewal/grace terms and public-key rotation notice                                                                                        | Maintain trusted clock, request renewal early, import locally with MFA, preserve last known-good state/evidence                                                                     |
| Isolation/access      | Maintain RLS and permission checks, document recovery/placement boundaries, provide tested security fixes                                                                                      | Keep app/owner/backup roles separate, test two named local MFA administrators, review identities/scopes and retain emergency access without shared credentials                      |
| Platform              | Document qualified topology, resource floor and compatibility                                                                                                                                  | Own host/hypervisor, kernel/Engine/Compose patches, capacity, TLS/DNS, firewall/egress, monitoring and physical/administrative security                                             |
| Key custody           | Document key formats, historical read-key requirements and signed-key update process; never require customer private keys for routine support                                                  | Generate/escrow field, historical, backup, database and JWT keys independently; test escrow recovery; approve rotation and access                                                   |
| Backups/recovery      | Supply integrity/recovery tooling and qualified runbooks; distinguish maintenance timing from service RTO                                                                                      | Own scheduled/offsite backups, joint DB/document/key consistency, retention, restore drills on a distinct host, current identity/payment reconciliation and agreed RTO/RPO evidence |
| Data residency        | Expose placement/residency inventory and no hidden vendor callbacks for core operations                                                                                                        | Approve all primary/replica/backup/log/support/notification/integration locations and providers; maintain evidence as infrastructure changes                                        |
| Incidents/support     | Agree escalation/response windows, emergency signed patch delivery, disclosure and offline evidence handling                                                                                   | Detect/escalate incidents, provide reviewed allowlisted diagnostics, authorize time-bound audited support access, apply approved patches and verify recovery                        |
| External side effects | Preserve business idempotency and document retry boundaries                                                                                                                                    | Reconcile payment, email/SMS/push/webhook and IdP state before resuming restored jobs/credentials; own provider contracts                                                           |

The parties must name service owners, security contacts, key custodians, backup owners and independent approvers. Agree offline transfer media, signature verification, support response hours, severity definitions, emergency response targets, planned patch cadence, renewal lead time, supported versions/end-of-support notice, customer maintenance approvals, temporary support consent and revocation. Record data minimization/retention and residency obligations for every support artifact. Support must not ask for unredacted databases, employee documents, field/backup keys, license private keys or general log dumps by default.

Before commercial acceptance, sign off the exact Linux/architecture/image matrix, clean-host and distinct-host drill reports, actual measured service RTO/RPO, restored-user/SCIM/SSO reconciliation, credential rotations and customer ownership of ongoing tests. A candidate bundle or native same-host rehearsal is insufficient acceptance evidence.
